# 網頁工作台：上傳 CSV、查異常與證據

## 目前完成

首頁 http://127.0.0.1:8000/ 已有操作介面，直接呼叫既有 API 與 PostgreSQL。
不用再透過 `/docs` 逐一輸入 run_id 或 case_id。

功能包含三份 CSV 上傳、基準設定、歷史批次、異常類型篩選、分頁、證據側欄及錯誤提示。
這台電腦既有的批次 #1、四筆異常可以直接在首頁查看，不必先重新上傳。

## 第 1 步：啟動服務（終端機執行）

如果服務已啟動，直接開啟首頁即可。需要重新啟動時，在原本啟動後端的終端機按 Control+C，再執行：

```bash
cd /Users/benson/Documents/ChatGPT/future/reconcile-platform
source .venv/bin/activate
python -m scripts.local_postgres start
python -m scripts.db init
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

不用安裝新套件、不需要 Node.js 或前端編譯指令。
本階段使用 HTML、CSS、原生 JavaScript，由 FastAPI 提供網頁與靜態檔案。
保持終端機開啟，使用瀏覽器操作。

## 第 2 步：開啟首頁（瀏覽器操作）

開啟 http://127.0.0.1:8000/ 。
右側會自動讀取最新的比對批次，顯示批次編號、異常總數與結算資料完整涵蓋日期。
範例資料應顯示批次 #1、四筆異常，清單列出 O1001～O1004。
資料庫不可用時會顯示讀取失敗，不會把錯誤當成零筆異常。

## 第 3 步：選擇 CSV 並比對（瀏覽器操作）

在左側「匯入資料」依序選擇：

| 欄位 | 範例檔案 |
|---|---|
| 訂單資料 | orders.csv |
| 付款資料 | payments.csv |
| 結算資料 | settlements.csv |

三份檔案都位於 `/Users/benson/Documents/ChatGPT/future/reconcile-platform/data/sample`。
檔案選擇視窗按 Command+Shift+G，貼上資料夾路徑即可前往。
首頁也提供可展開的「範例 CSV 在哪裡？」說明。

範例資料沿用以下設定：

- 比對基準時間：2026/11/17 09:00，台北時間。
- 結算資料完整涵蓋至：2026/11/16（含當日）。
- 訂單同步等待時間：15 分鐘。

按「上傳並比對」。上傳期間按鈕與表單會暫時停用，完成後恢復。
目前資料已存在，因此預期提示「已沿用批次 #1，共 4 筆異常。」
右側自動切換到這次回傳的批次。相同資料與設定不會重複建立四筆案件。
如果上傳失敗，左側顯示錯誤；右側原本已載入的批次仍是先前成功儲存的結果。

## 第 4 步：查看異常與篩選（瀏覽器操作）

右側「異常清單」可看到訂單、付款編號、異常類型與差額。

| 訂單 | 類型 | 差額 |
|---|---|---|
| O1001 | 訂單狀態未更新 | — |
| O1002 | 付款金額不符 | -100.00 |
| O1003 | 結算紀錄缺漏 | — |
| O1004 | 結算算式不符 | 10.00 |

「—」表示該規則沒有金額差額欄位，不代表資料遺失。
差額定義會在案件詳情中顯示：付款金額差額表示少付／多付；結算算式差額表示紀錄淨額偏高／偏低。

在「全部異常類型」下拉選單選「結算算式不符」，應只剩 O1004。
上方「異常總數」仍顯示整批四筆，下方「異常清單」計數顯示篩選後的一筆。
切回「全部異常類型」會重新顯示四筆。
每頁最多 10 筆；資料更多時使用上一頁／下一頁。
歷史批次一次載入 50 筆，有更多時會出現「更多批次」。

## 第 5 步：查看原始證據（瀏覽器操作）

在 O1004 那一列按「查看證據」。
側欄顯示 S8004、總額 2,000、手續費 40、紀錄淨額 1,970、應有淨額 1,960、差額 10。
往下捲動側欄查看兩份原始證據：

- settlements.csv 第 4 列。
- payments.csv 第 5 列。

證據以中文欄位顯示，也能展開「查看完整 JSON」。
點右上角 × 或按 Escape 可關閉側欄。

再打開 O1003 的證據，往下找到「查無對應結算」。
應顯示搜尋付款 P9003、符合筆數 0、掃描筆數 4、完整涵蓋至 2026-11-16。
這就是 API 中 `absence_check` 的網頁呈現，沒有虛構不存在的結算列號。

## 閱讀說明，不需要貼上或單獨執行

| 檔案 | 用途 |
|---|---|
| app/web/index.html | 表單、異常表格與證據側欄結構 |
| app/web/style.css | 桌面與窄螢幕版面、表格與側欄樣式 |
| app/web/app.js | 呼叫 API、上傳與載入狀態、篩選、分頁與證據呈現 |
| app/main.py | 首頁路由與 /static 靜態檔案 |

畫面只透過 API 存取資料，JavaScript 不包含資料庫密碼。
CSV 原始文字使用 `textContent` 呈現，不當作 HTML 執行。
快速切換批次或篩選時，舊請求的結果不會蓋掉新選擇。
案件狀態、備註與結案已於下一階段完成，請看 [案件處理說明](case-workflow-step-by-step.md)。
目前沒有登入、派工或 AI 摘要，服務維持本機使用。
