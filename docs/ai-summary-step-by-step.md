## 第 2 步：了解摘要會包含什麼（閱讀，不需執行）

| 區塊 | 內容 |
|---|---|
| 摘要概述 | 說明這筆案件發生了什麼資料差異 |
| 證據重點 | 整理原始資料支持的事實，附 E1／E2 等引用 |
| 待驗證推測 | 可能原因與驗證方式；不當作已確認根因 |
| 建議查核步驟 | 人工接下來可以核對哪些檔案、紀錄與流程 |
| 尚缺資料 | 目前還缺少的確認依據 |

以 O1004 為例，已知是總額 2000、手續費 40、紀錄淨額 1970。
依算式應為 1960，差額為 10。AI 應整理這些資料，提出下一步查核建議；
不能憑空宣稱匯入程式已確認有錯，或真的多入帳 10 元。
實際文字將由模型產生，測試範例不代表之後的固定回答。

每個事實、推測與建議至少引用一個存在的證據編號。
點引用按鈕會跳到案件側欄的原始證據；查無紀錄的證據則呈現搜尋條件與完整涵蓋範圍。
後端驗證引用編號存在與結構正確，不等於已證明每句模型文字正確，仍要人工核對。

## 第 3 步：之後準備好金鑰時（自己的終端機執行）

參考 OpenAI 官方 quickstart 準備自己的 API 金鑰：
https://developers.openai.com/api/docs/quickstart

不要把金鑰貼到聊天裡。先在專案啟用虛擬環境：

```bash
cd /Users/benson/Documents/ChatGPT/future/reconcile-platform
source .venv/bin/activate
python -m scripts.configure_ai
```

終端機會提示輸入金鑰，輸入時不顯示字元；完成後按 Enter。
程式保留 DATABASE_URL，將金鑰與預設模型 gpt-5-mini 存進本機 .env，檔案權限設為 600。
不會在網頁或輸出中顯示金鑰，.env 已被 Git 忽略。
如果環境變數本來已設定 OPENAI_API_KEY／OPENAI_MODEL，會優先於 .env。

然後在原本啟動後端的終端機按 Control+C，重新執行：

```bash
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

本階段的 SDK 與 migration 3 已安裝／套用；重建環境時先安裝 requirements-lock.txt 並執行 scripts.db init。

## 第 4 步：之後真正產生摘要（瀏覽器操作）

重新整理首頁，打開案件，確認摘要區顯示已設定模型。
按「產生 AI 摘要」後才會呼叫 OpenAI；單純開啟案件不會呼叫模型。
真正呼叫會使用你的 API 額度，需帳戶與模型有可用權限。

按鈕會暫時停用，完成後顯示摘要、證據引用、模型、來源案件版本與時間。
來源資料只包含此案件的異常、狀態與證據必要欄位；處理備註、資料庫設定及其他 CSV 額外欄位不會送出。
其中訂單編號、金額等必要欄位的值會傳送至 OpenAI，網頁已在按鈕旁說明。

摘要與輸入快照保存在 case_ai_summaries，不會改動案件狀態、處理歷程或原始資料。
頁面關閉後，再開啟同一案件可讀取保存結果，不必再次呼叫模型。

## 第 5 步：快取與舊版本提示

相同案件版本、模型與提示詞版本會沿用已儲存摘要。
再按「讀取目前版本摘要」會顯示「未再次呼叫模型」。
若案件新增備註或改變狀態，版本會增加，舊摘要顯示過期提示。
要以新版案件重新整理時，再按「依最新案件產生摘要」。
如果產生期間案件被更新，摘要仍保留原版本，並標示過期，不會覆蓋新的人工處理進度。
目前備註本身不傳送給模型，因此新版摘要不會轉述備註內容。

## 失敗情況

- 未設定金鑰：提示尚未啟用，不呼叫模型。
- 金鑰／模型不可用、額度不足或連線失敗：顯示明確錯誤，不提供假摘要。
- 模型拒絕、回應未完成、格式錯誤或引用不存在的證據：不儲存該次結果。
- 同一案件已在產生摘要：回傳 409，稍後再讀取；避免同時重複呼叫。

程式設定每次模型請求最多 4000 輸出 token、45 秒逾時，SDK 不自動重試。
同一案件原本的儲存、備註與證據查詢不受 AI 失敗影響。

## 閱讀說明，不需貼上或單獨執行

| 檔案 | 用途 |
|---|---|
| app/ai_summary.py | 整理白名單輸入、結構化摘要、引用檢查、呼叫模型、快取與保存 |
| sql/003_ai_summaries.sql | 摘要、輸入快照、模型與使用量紀錄 |
| scripts/configure_ai.py | 本機隱藏輸入金鑰，保留資料庫設定 |
| app/api.py | AI 設定狀態、讀取摘要與按需產生摘要 API |
| app/web/app.js | 摘要區、引用按鈕、讀取狀態與過期提示 |

採用官方 Responses API 與 Structured Outputs，透過 Pydantic 定義回應結構。
請求設定 store=False，不使用模型工具或自動執行 SQL。

官方參考：

- https://developers.openai.com/api/docs/guides/structured-outputs
- https://developers.openai.com/api/docs/models/gpt-5-mini

API：

- GET /api/ai/status：是否設定完成與模型名稱，不回傳金鑰。
- GET /api/cases/{case_id}/ai-summary：讀取最新保存結果與過期標記，不呼叫模型。
- POST /api/cases/{case_id}/ai-summary：產生或沿用目前版本摘要。
