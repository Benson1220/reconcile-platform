# 案件狀態、處理備註與結案

本階段已套用 migration 2，既有四筆案件預設為「待處理」，原始來源與比對證據保留。
不需要安裝新套件。正式工作台：http://127.0.0.1:8000/ 。

## 第 1 步：重新整理首頁（瀏覽器操作）

維持後端執行，重新整理首頁。清單會多出「處理狀態」欄位，並有「全部處理狀態」篩選。
現在原有 O1001～O1004 都應是「待處理」。
如果沒有新欄位，按 Command+Shift+R 重新讀取網頁資源。

資料庫升級已完成。若在另一台電腦或需要確認時，可在已啟用環境的專案終端機執行：

```bash
python -m scripts.db init
```

預期顯示 `OK 資料庫 schema 已就緒（migration 1, 2）`。
原本 SQL migration 1 沒有被改寫，migration 2 是新增欄位與歷程資料表，不會清除既有資料。

## 第 2 步：開始調查（瀏覽器操作）

1. 在 O1004 那一列點「查看證據」。
2. 側欄找到「案件處理」。
3. 「更新處理狀態」選「調查中」。
4. 「新增處理備註」填寫：

> 操作練習：開始核對 S8004 的總額、手續費與淨額，確認 10 元差異來源。

5. 點「儲存處理紀錄」。

應顯示「處理紀錄已儲存」，狀態改成調查中，版本由 1 增為 2。
「處理紀錄（1）」顯示儲存時間、待處理 → 調查中，以及你的備註。
關閉側欄後，清單的 O1004 也會顯示調查中。

## 第 3 步：補充備註（瀏覽器操作）

再次開啟同一案件，保持「調查中」，新增備註後儲存即可。
即使狀態不變，也會新增一筆歷程，並顯示「調查中 · 新增備註」。
每次備註必填，去掉前後空白後最多 2,000 字；備註不會覆蓋前一次內容。
目前介面沒有修改或刪除已儲存歷程的功能。

## 第 4 步：練習結案（瀏覽器操作）

在 O1004 的案件處理中選「已結案」，填入明確的處理說明，再儲存。
這組模擬資料可使用以下練習備註：

> 操作練習：完成證據核對，2000 − 40 應為 1960，紀錄淨額 1970 偏高 10 元。本次僅練習結案流程。

應看到「已結案」、結案時間與新的處理紀錄。
目前允許直接從待處理結案，或先經調查中再結案；每次都必須有說明。
已結案時仍能補充備註，不會改變原結案時間。

結案代表案件處理狀態，不會修改原 CSV、比對結果或證據。
因此整批異常總數仍為四筆；它是歷史偵測結果，不是未結案筆數。

## 第 5 步：依狀態追蹤（瀏覽器操作）

關閉側欄，清單上方選「已結案」，應只看到剛結案的案件。
改選「待處理」可查看剩餘待處理案件。
狀態與異常類型可以一起篩選，兩個條件都符合才顯示。
案件儲存後不再符合目前篩選時，會從這個清單中移除，但側欄仍會顯示儲存成功。

## 第 6 步：重新調查（瀏覽器操作）

打開已結案案件，把狀態改為「調查中」，填寫重新調查的原因，再儲存。
目前結案時間會清空，先前的結案事件與備註仍保留在歷程。
重新結案後會記錄新的結案時間。

## 第 7 步：驗證資料保留（瀏覽器操作）

重新整理首頁，再開啟案件，確認狀態與所有備註仍存在。
上傳完全相同 CSV、相同設定與相同規則版本，會沿用原案件，狀態與歷程也會保留。
若 CSV 或比對設定不同而建立新批次，那是新的一組案件，不會自動繼承其他批次的處理進度。

## 多分頁更新衝突

每次儲存會送出你讀取時的 `expected_version`。
若另一個分頁先儲存，舊版本更新會收到 HTTP 409，避免覆蓋新進度。
側欄會保留草稿，並提供「重新載入案件，保留草稿」按鈕。
重新載入後先核對最新歷程，再決定是否送出；不會自動重送。

## 閱讀說明，不需要貼上或單獨執行

| 檔案 | 本階段改動 |
|---|---|
| sql/002_case_workflow.sql | 新增 status、version、updated_at、closed_at 及 case_events |
| app/database.py | 自動套用編號 migration、鎖定案件、檢查版本、原子更新狀態與歷程 |
| app/api.py | PATCH 案件、備註驗證、狀態查詢篩選 |
| app/web/app.js | 處理表單、歷程、狀態篩選與衝突草稿保留 |

新增 API：`PATCH /api/cases/{case_id}`，JSON 欄位為 `status`、`note`、`expected_version`。
狀態代碼：OPEN（待處理）、IN_PROGRESS（調查中）、CLOSED（已結案）。
GET 案件詳情會回傳 `history`，每筆包括變更前後狀態、備註、版本及時間。
GET 批次案件清單可加 `status` 參數。

狀態與事件以同一交易儲存。尚未加入登入，因此歷程目前不標示已驗證的處理人身分。
